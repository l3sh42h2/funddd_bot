# M0 — база для M1/M2

Исполнитель Codex. Код a976bec, отчёт о выкате 0f88fd7; ТЗ 9d80256.
Полный SHA-256 манифест src/deploy/tests/pyproject в M0_MANIFEST.json: пропущенных и отличающихся файлов нет.
Дополнительные файлы VPS — только setuptools egg-info. Три прежние службы active, 0 рестартов на срезе.
В локальной копии Claude нет незакоммиченного кода (только untracked .venv). Его патчноут имеет deployed.

Согласованная SQLite backup создана backup API на VPS в runtime/migration_backups (путь/хеш в манифесте),
chmod 0600; исходная БД открывалась mode=ro. База и реальные записи не копируются в Git. quick_check=ok.
На срезе: одна OPEN сделка и одна ABORTED; активных intents нет, один BALANCED clip, отправленных/неизвестных
DEX/perp попыток нет; SOL operations/attempts пусты. Это состояние журнала, не новая сверка биржевых API.
Перед переключением M5 требуется повторный срез и сверка площадок: M0 не даёт разрешения на основе старых данных.

M1/M2 сохраняют существующие engine/SolEngine, registry, расчёт PnL и resume. Новые таблицы только core_*.
Незавершённые core-команды после restart не переисполняются вслепую: явный interrupted + уведомление; старые
approved/running остаются под существующей startup reconciliation. Никаких авто-входов, resize или SL.
Миграция Telegram offset берёт максимум сохранённого offset и истории обработанных updates; старые pending
планы истекают при startup. Проверки берут существующие EVM/SOL синтетические fixtures, без реальных ключей.

Промежуточный M2 — реализация в отдельной ветке. Боевой выкат и изменение пользователей VPS не входят в эту
итерацию: смена units/env/прав документируется и проверяется на изолированных fixtures для M5.
Общий execution lock нужно установить также старому trader перед переходом. Старые бинарники без него нельзя
оставлять под автоматическим restart при первом переключении. Откат никогда не заменяет trade.db backup-копией.
