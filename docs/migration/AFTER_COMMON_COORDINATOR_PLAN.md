## 1. Завершить приёмку текущего пакета

- Claude получает diff от 0f9037c до b6832d7, M4_COMMON_COORDINATOR_RESULT.md,
  ADAPTER_GUIDE.md, профильную матрицу, differential и точный Linux receipt.
- Особое внимание: общая атомарная граница root/intent/deal, UNKNOWN и резерв,
  обе account/instrument scopes, native quantity против журнала, margin/fee units,
  TTL первого dispatch и разрешение защитного hedge после истечения TTL.
- Существенные замечания исправляются в новом кандидате. Повторяются затронутые
  проверки; release receipt должен соответствовать фактически выпускаемым байтам.
- Перед выкатом: свежая база релиза и чужие изменения, текущие открытые позиции,
  offline exit/recovery для каждой, read-only venue-сверка. Затем штатный deploy,
  drain, reader floor, запрет несовместимого rollback и postcheck трёх процессов.
- Выход этапа: closure ревью + receipt + установленный SHA + свежий postcheck.
  Никаких тестовых реальных сделок или новых разрешённых торговых сочетаний.

## 2. Аудит полноты учёта

- Зафиксировать единый as_of и scope каждой площадки/аккаунта/позиции.
- Сверить все страницы fills, комиссии, funding, cash movements и остатки;
  обнаружить пропуски, дубли, поздние исправления и неоднозначные native references.
- Разделить contracts, underlying, base fee, quote fee и margin currency.
  Не складывать валюты без доказанного курса и времени оценки.
- Проверить cost basis, realized/unrealized PnL, возвратные расходы и полноту периода.
  Неизвестная комиссия или неполный funding не становятся нулём.
- Rebuild на одном наборе исходных фактов должен дать те же quantities/cash.
  Исторические исправления оформляются отдельными прослеживаемыми фактами.
- Выход: reconciliation report с доказанными совпадениями и явными unknown;
  спорные суммы не скрываются агрегированным PnL.

## 3. Окончательная приёмка трёх процессов

- Закрыть оставшуюся зависимость legacy execution от Telegram formatters:
  engine.py / sol_flow.py → нейтральные domain notifications → interface presenter.
  Core не должен знать транспорт Telegram; DTO и исторические сообщения совместимы.
- Проверить AC-01…29 по фактической evidence-матрице, не по числу модулей.
- Сквозные сценарии: падение interface/collector/core, повтор команды, UNKNOWN,
  drain/restart, reader/schema compatibility, конфликт выката и свежесть read-model.
- Выход: по каждому критерию принятое доказательство или открытый пункт с причиной.
  До этого не объявлять миграцию целиком завершённой.

## 4. Следующий функциональный патч: resize и SL

- Добор/сокращение — отдельная одобряемая операция существующей позиции,
  замороженные legs/account scopes, delta target, общий root/journal и фактический
  net hedge. Старый размер не перезаписывать до подтверждённых исполнений.
- Пересчитать cost basis, комиссии, количество и риски; partial/UNKNOWN сохраняют
  реальный остаток, повтор команды не удваивает операцию.
- При новом входе пользователь задаёт цену SL. Native stop на фьючерсе должен быть
  reduce-only и иметь сохранённый scoped ID; сверка позиции раз в минуту.
- После доказанного срабатывания stop продать соответствующий остаток спота через
  общий executor. Просто касание цены или отсутствие ордера в одном ответе API
  не являются доказательством fill. Crash/partial/UNKNOWN не дублируют продажу.
- Совместное поведение resize + stop: изменить защищаемое количество согласованно,
  без окна с удвоенным стопом и без незаметно незащищённого добора.
- Выход: самостоятельное ТЗ/патч, профильные fault tests, ревью и отдельный выкат.

## 5. Новые реальные адаптеры

Владелец выбирает биржу и исполнителя. Типы: CEX spot, CEX futures, DEX spot EVM,
DEX spot Solana, DEX futures. Для каждого: native API/signing, scoped identity,
capabilities/precision/account mode, execution bounds, fee/margin model,
prepare/submit/resolve/cancel/recovery, регистрация/config и сквозные tests.
Synthetic examples доказывают контракт расширяемости; не заменяют проверку API.
Каждая новая live-площадка включается явно с лимитами. Совместимость collateral,
underlying и modes проверяется до действий; USDC=USDT не предполагается.
