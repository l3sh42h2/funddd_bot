Основание: предложение Codex `/Users/admin/Documents/hyper/reviews/FUNDING_CODEX_CLAUDE_COORDINATION_PROPOSAL.md`

## 1. Кто что делает — решает владелец
- Владельца каждой задачи, исполнителя и ревьюера назначает владелец. Агенты задачи между собой не делят и чужие не
  забирают.
- Перед началом задачи агент проверяет пересечение с незаконченными задачами другого агента: движок, учёт денег,
  схема БД, выкат, общие файлы. Если пересечение есть — сообщает владельцу риск и ждёт его решения (параллельно,
  подождать, кому ревью).
- Денежный код ревьюит тот, кого назначит владелец; уровень модели ревью — по `vps/CLAUDE.md`.

## 2. Код и рабочие копии
- Общая история — приватный репозиторий GitHub. Каждый агент работает в своей рабочей копии и своей ветке:
  `claude/<задача>`, `codex/<задача>`. Одновременно одну папку не правят.
- Базовая версия R0 — код, выкачанный на VPS 13.09.2026 13:51 UTC (фаза 1 + рейтинг A/B/C), сверенный по SHA-256
  всех 147 файлов с сервером: `/Users/admin/Documents/vps/funding_bot_releases/R0/`.
- В Git НИКОГДА: `.env*`, `runtime/`, базы (`*.db`), логи, ключи, botLP, подписанные транзакции. Перед каждым
  пушем — проверка кода на точные значения ключей (имена файлов, без значений).
- Отсутствие Git-конфликта не доказывает, что денежные инварианты целы: объединённую версию проверяют тесты и ревью.

## 3. Патчноуты
Каждое изменение — свой файл `PATCHNOTES/<change_id>.md`: автор, задача, исходная база (релиз/SHA), проблема и
результат, затронутые файлы и инварианты, проверки, миграции и совместимость с открытыми сделками, ограничения
отката. Один общий файл одновременно не правят.

## 4. Выкат — один путь для обоих
Выкат только через `deploy/deploy.sh` (тесты на Маке и на сервере, замок, проверенная прежняя версия, автооткат).
Руками файлы на VPS не правят и службы в обход не перезапускают.

Принятый минимум, который ЕЩЁ НЕ ВНЕДРЁН (внедряет тот, кому поручит владелец):
- весь серверный цикл выката — одним процессом под `flock` на сервере (обрыв связи с Маком ничего не ломает);
- `release-state.json`: номер релиза и SHA; выкат с устаревшей базы — отказ `STALE_BASE` без замены файлов;
- обязательный патчноут для выката;
- трейдер сообщает свою версию в `/status`; выкат не считается успешным, пока трейдер не запущен на новой версии;
- отказ до переключения не выдаётся за «откат» (сейчас любой сбой `remote_switch.sh` запускает общий откат);
- drain трейдера перед переключением: новые операции не принимаются, неизвестные исходы разрешены.
Уже работает: замок `mkdir` с токеном, `.prev` = последняя проверенная версия, ворота трейдера (одобренные/
выполняющиеся операции), ворота множителя контрактов при откате.

## 5. Открытые позиции
Открытая захеджированная сделка сама по себе не запрещает выкат, если новая версия умеет её восстановить.
Откат кода не восстанавливает старую `trade.db` поверх состоявшихся сделок.
