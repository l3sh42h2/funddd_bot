# Матрица приёмки перехода на три процесса

Источник: [THREE_PROCESS_MIGRATION_TZ.md](THREE_PROCESS_MIGRATION_TZ.md).
Статус всех пунктов: **не проверено** при создании ТЗ. Реализация не объявляется готовой по наличию документа.
Каждый пункт получает test/evidence reference, SHA, runtime fingerprint и результат; исключения с причиной
не превращаются в passed. Проверки на фейках используют синтетические ключи и не отправляют ордера.

| ID | Сценарий | Критерий |
|---|---|---|
| AC-01 | Core без TG_BOT_TOKEN и без UI | Стартует, восстанавливает журналы; Telegram не нужен торговому loop |
| AC-02 | UI упал/перезапущен при начатом действии | Core не прерывает обязательное разрешение исхода, результат доставляется после восстановления |
| AC-03 | Два core или старый trader + core | Второй не получает execution lock и не отправляет ни одного внешнего действия |
| AC-04 | Повтор команды/callback после потери ответа | Один durable request и одна операция; тот же key с иным payload отказан |
| AC-05 | Чужой пользователь/peer, старая кнопка, TTL/nonce/hash mismatch | Отказ до торговых побочных эффектов |
| AC-06 | Core недоступен | UI не заявляет исполнение; повтор запроса сохраняет key и не выполняет старое одобрение по новым ценам |
| AC-07 | Проверка прав/импортов | UI/collector не читают trading secrets, UI не открывает trade.db; core не зависит от Telegram/presenters |
| AC-08 | Снимок старый/частичный/неизвестной версии | Явный stale/unsupported; запрет решений, требующих свежести, без подмены возраста временем ответа |
| AC-09 | Публичный dashboard и приватный кабинет | Позиции/ключи/подписи не утекли в публичный DTO; прежняя авторизация и сессии сохранены |
| AC-10 | Большая таблица и медленный браузер | Health ≤16 KiB без чтения таблицы/биржи; p95 <200 мс на зафиксированном профиле; core responsive |
| AC-11 | EVM-spot fake × Aster/Gate/HL contract adapters | Сборка из независимых LegSpec; режимы/ключи одной ноги не зависят от лишнего профиля |
| AC-12 | SOL-spot fake × Aster/Gate/HL contract adapters | Координатор не требует HL account methods для остальных адаптеров |
| AC-13 | CEX-spot fake и perp/perp fake | Не нужны фиктивные wallet/allowance/gas; правильно считаются обе экспозиции и разные валюты |
| AC-14 | Несовместимый инструмент/capability/режим | Отказ до отправки; новая комбинация не включается live автоматически |
| AC-15 | Replay существующих EVM/SOL сделок | Количества, cash flows, fees, funding, cost basis, PnL и статусы эквивалентны на одном срезе |
| AC-16 | Сбой после подписи, отправки, ACK, partial, finality, перед commit | Неизвестное восстанавливается; нет двойного swap/order и повторного списания бюджета |
| AC-17 | Несколько страниц fills / дубли / разные аккаунты с одинаковыми ID | Нет потерь и двойного учёта; сохранены корректные namespace ключей |
| AC-18 | Старые inst_json/hash, multiplier≠1, EVM-case, Solana mint | Исторические hashes/ID сохранены, единицы и идентичность не ослаблены |
| AC-19 | Незавершённые legacy/SOL operations и резервы | Нет второй активной операции и двойного резервирования; ручной resume остаётся ручным |
| AC-20 | Read model rebuild и уведомление с повторной доставкой | Восстановление из доказанных фактов; дубль уведомления не создаёт торговое действие |
| AC-21 | Повторный deploy того же проверенного артефакта | Повтор preflight/health, без полного pytest; изменённый hash/runtime отменяет reuse |
| AC-22 | Чужой релиз после подготовки, обрыв SSH, параллельный deploy | STALE_BASE до изменения; один server job/lock; обрыв SSH не оставляет два владельца исполнения |
| AC-23 | Drain при in-flight/UNKNOWN | Нет нового риска, начатые действия разрешаются; небезопасное переключение отказано |
| AC-24 | Backup/migration повторно и ошибка пути БД | Согласованный backup WAL; миграция идемпотентна; нет тихо созданной пустой trade.db |
| AC-25 | Откат после состоявшихся сделок | Код меняется только на совместимый reader, новые исполнения/балансы не затираются старой БД |
| AC-26 | UI-only релиз, несовместимый IPC, смешанные версии | Core не рестартует при доказанной совместимости; несовместимая комбинация не принимает команды |
| AC-27 | Итоговая проверка VPS | Три целевых Python-службы, старые trader/web не активны, версии совпали, текущие позиции/очереди сверены |
| AC-28 | Проверка scope релиза | Новые команды resize/SL, защитные ордера и новые live-стратегии не включены миграцией |
| AC-29 | Подключение четырёх классов: CEX spot/futures, DEX spot/futures | Пять независимых fake-адаптеров: CEX spot, CEX futures, DEX spot EVM, DEX spot Solana, DEX futures; шаблон и инструкция; совместимые пары собираются через общий registry; diff не меняет координатор/учёт/UI, неподдержанные capabilities отказаны |

## Минимальный набор артефактов приёмки

- Полный исходный и установленный source/artifact manifest, не только sample файлов.
- Schema/IPC/config versions и список совместимых readers; действительная граница отката.
- Replay report со срезом данных, несовпадениями и правилами округления; неизвестные значения не обнуляются.
- Contract/operation/recovery/deploy тесты и список обоснованных skips; fixture hashes без секретов.
- Отчёт независимого ревью и закрытие существенных замечаний.
- Release receipt с PID/boot epoch/build hashes, состоянием drain, источниками freshness и проверкой открытых сделок.
- Фактическое время этапов и доступная статистика моделей; список оставшихся ограничений.

## Уточнения тестовой матрицы

Aster/Gate/HL в AC-11/12 — контрактные тесты адаптеров с записанными/синтетическими ответами и подходящими рынками,
не утверждение о наличии одной монеты сразу на всех биржах. В live принимаются только ранее разрешённые комбинации.
CEX/perp-perp из AC-13 доказывают архитектурную независимость; реальные новые площадки и стратегии — отдельные задачи.
Сценарий AC-16 покрывает обе сети: EVM nonce/receipt и Solana blockhash/финальность; CEX partial/cancel/unknown также.
Тестовая нагрузка AC-10 фиксирует железо/размер таблицы/число клиентов/длительность. По одному быстрому запросу SLA
не считается выполненным. Нагрузочный тест не проводить на боевом VPS с открытыми сделками.
