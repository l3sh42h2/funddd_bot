# ANSEM: одинаковый счёт HL с разным регистром адреса

Автор: Codex. Задачу исправить отказ входа назначил владелец в FUNDING.
База: cb00a77 (ветка claude/sol-hl). Все 286 присутствующих файлов базы сверены по SHA-256 с VPS;
два дополнительных файла базы — ранее опубликованные патчноуты, отсутствовавшие на VPS.

Runtime приводит EVM-адреса мастера и торгового счёта Hyperliquid к lowercase, а реестр может хранить checksum-case.
Буквальное сравнение этих scope останавливало ANSEM до формирования плана, хотя адреса обозначали один счёт.

При создании новой спецификации нормализуются только два валидных 20-байтовых EVM-адреса внутри формата
`hyperliquid:<network>:<master>:<account>:<dex>`. Network/dex/venue и opaque/legacy ID сравниваются точно.
Другой счёт продолжает отклоняться. Исходная запись реестра, её хеши и уже сохранённые JSON сделок не меняются;
mint Solana и fullcoin HL остаются чувствительными к регистру. Миграция БД не нужна.

Изменения:
- src/funding_bot/trade/instruments.py — нормализация при создании deal_spec, до проверки равенства счетов;
- tests/test_hl_account_scope_case.py — 14 регрессионных случаев;
- этот патчноут.

Штатный deploy/deploy.sh повторно выполняет полный набор локально и на сервере перед переключением.
Команды входа, подписи, отправка ордеров и изменение пользовательских лимитов не входят в эту правку.
При откате к прежнему коду ошибочный отказ checksum-case вернётся; ранее созданные спецификации не мигрируются.
